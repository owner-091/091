# Train Game — Current Design Baseline

이 문서는 현재까지 확정된 게임 방향을 개발 기준으로 정리한 문서입니다.

## 1. 화면과 플레이어

- 게임은 **2D 탑뷰 형식의 도트 게임**입니다.
- 플레이어는 열차 자체가 아니라 **차장 캐릭터**를 직접 조종합니다.
- 게임 시작 지점은 열차 내부이며, 초반 튜토리얼도 열차 안에서 진행합니다.
- 열차는 플레이어의 이동 거점이자 생활 공간입니다.
- 열차는 파손되지 않습니다.

## 2. 열차 내부 플레이

차장은 열차 내부를 직접 이동하며 다음 요소를 관리합니다.

- 화물 확인
- 손님 상태 확인 및 접객
- 승무원 배치
- 손님 식당 확인
- 승객과의 대화

관리 요소는 실패를 막기 위한 생존 시스템이 아닙니다. 플레이어의 행동과 대화가 세계관, 관계, 사건의 맥락을 풍부하게 만드는 방향으로 사용합니다.

승객 대화는 중요한 콘텐츠입니다. 특히 다음 역에서 일어날 메인 이벤트의 복선이나 소문을 열차 안의 대화에 자연스럽게 포함할 수 있습니다.

## 3. 승객

- 주요 승객은 이름, 성격, 목적, 관계, 과거를 가진 입체적인 캐릭터로 만듭니다.
- 모든 배경 승객까지 같은 수준으로 구체화할 필요는 없습니다.
- 주요 승객은 여러 구간을 함께 여행하거나 서로 다른 사건에 재등장할 수 있습니다.

## 4. 역과 이벤트

각 역의 기본 콘텐츠 단위:

- 서브 이벤트 2~3개
- 메인 이벤트 1개

정차 시간은 실제 랜덤 타이머로 결정하지 않습니다.

각 사건에 필요한 기간을 기획 단계에서 정하고, 그 진행에 맞춰 정차 시간을 구성합니다. 다만 플레이어에게는 열차의 실제 운행 사정 때문에 정차 시간이 매번 달라지는 것처럼 느껴지게 합니다.

메인 이벤트의 마지막 선택은 다음에 향할 노선 또는 목적지를 결정하는 데 사용합니다.

## 5. 이동 중

역과 역 사이의 이동 중에는 메인 이벤트급 사건보다는 작은 사건이 간헐적으로 발생합니다.

예:

- 승객과의 대화
- 승객 사이의 작은 문제
- 접객 요청
- 식당이나 화물 관련 상황
- 승무원과의 대화
- 창밖이나 방송을 통해 전달되는 세계 정보
- 다음 역 사건의 복선

## 6. 노선

세계 이동은 **노드형 노선 지도**를 사용합니다.

플레이어가 단순히 지도에서 원하는 노드를 고르는 것보다, 역의 메인 이벤트 마지막 선택이 이후 갈 수 있는 노선을 결정하는 구조를 기본으로 합니다.

## 7. 성공과 실패

이 게임에는 일반적인 의미의 패배나 게임오버가 없습니다.

- 어떤 선택을 해도 이야기는 계속 진행됩니다.
- 선택에 따라 이후 사건과 관계, 기록, 최종 결말이 달라집니다.
- 장기적인 플레이 목적은 세계를 여행하며 인물과 사건을 만나고 **기록을 모으는 것**입니다.

## 8. 현재 개발 우선순위

사건 시스템을 완성하기 전에 열차와 여행의 물리적인 플레이 기반부터 검증합니다.

1. 탑뷰 차장 이동
2. 열차 내부 공간과 객차 연결
3. NPC 접근 및 상호작용
4. 최소 대화 UI
5. 정차 / 출발 / 운행 / 도착 상태
6. 노드형 노선 데이터
7. 역 전환
8. 관리 기능
9. 사건 및 분기 시스템

이 문서에 없는 세부 규칙은 아직 미확정으로 간주합니다.
